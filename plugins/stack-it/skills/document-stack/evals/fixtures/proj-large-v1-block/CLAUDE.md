- No new dependency without a line in the PR description saying why.

### Conventions

- Route handlers live under `app/api/<name>/route.ts` and always return `NextResponse.json`.
- Server actions go in `app/actions/`, one file per domain, each starting with `"use server"`.
- Anything shared between server and client goes in `lib/`; anything client-only goes in `components/`.
- Environment variables are read once, in `lib/env.ts`, through a Zod schema. No `process.env` anywhere else.
- Every table in `db/schema.ts` carries `createdAt` and `updatedAt` with database defaults, never application timestamps.
- MDX content files are named `content/<section>/<slug>.mdx` and the slug is the URL. Renaming one needs a redirect in `next.config.ts`.

### Gotchas

- Turbopack serves stale CSS after renaming a module. Restart the dev server; a hard refresh does not clear it.
- `pnpm build` runs the Sentry plugin, which fails soft. A build that says "source maps skipped" is a missing token, not a warning to ignore.
- Neon suspends an idle branch. The first request after a quiet period takes about two seconds, which reads like a hang in local dev and is not one.
- The Stripe webhook signature check fails against a body Next has already parsed. Do not add a body parser to that route.
- `pnpm test:e2e` against a dev server picks up hot-reload flakes. Run it against `pnpm build && pnpm start`.
- `pnpm db:migrate` against a Neon branch that another preview is using locks the table for the length of the migration. Branch first.
- A server action that throws inside a transaction returns a generic error to the client by design. The real message is in Sentry, not in the browser console.
